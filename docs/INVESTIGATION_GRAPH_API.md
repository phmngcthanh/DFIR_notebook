# Investigation Graph — Function and Data Contract Reference

Document version: 1.1 (implemented — companion to [INVESTIGATION_GRAPH_PLAN.md](INVESTIGATION_GRAPH_PLAN.md))

This document defines every new function with its exact inputs and outputs so the
contracts can be consumed anywhere: from the React frontend over Tauri IPC, from the
portable JSON formats by other tools/languages, or reimplemented against another shell
(e.g. the `server` branch HTTP surface).

Conventions (unchanged from the existing app):

- All Tauri commands return the standard envelope
  `{ "success": bool, "data": <T> | null, "error": string | null }` (`ApiResponse<T>`).
- Ids are UUID strings generated by the backend. Timestamps are RFC 3339 UTC strings
  (`"2026-07-25T14:03:00.000Z"`). Optional fields accept `null`.
- Command parameters cross the IPC boundary in camelCase (e.g. `iocId`); stored/JSON
  entity fields are snake_case (e.g. `ioc_id`) — identical to existing commands.
- Every mutating command requires an unlocked case and an active expert, runs in one
  SQLite transaction, and (for evidence entities) records one history commit.

## 1. Data types

### 1.1 `IocSighting` (evidence)

```json
{
  "id": "uuid",
  "ioc_id": "uuid",
  "ioc_value": "185.220.101.4",          // read-model projection, not stored
  "ioc_type": "IP",                       // projection
  "threat_level": "high",                 // projection
  "entity_kind": "asset",                 // asset | network | firewall
  "entity_id": "uuid",
  "entity_name": "DC-01",                 // projection
  "sighted_at": "2026-07-20T02:14:00.000Z",  // nullable
  "location": "C:\\Windows\\Temp\\payload.exe",
  "note": "Found during triage of scheduled tasks",
  "created_at": "2026-07-21T09:00:00.000Z"
}
```

Storage uses three nullable FK columns (`asset_id`/`network_id`/`firewall_id`, exactly
one set); the API exposes the pair `entity_kind` + `entity_id`. Projections
(`ioc_value`, `entity_name`, …) are joined at read time and ignored on input.

### 1.2 `AttackEdge` (evidence)

```json
{
  "id": "uuid",
  "source_kind": "external",              // asset | network | firewall | external
  "source_id": "Internet",                // UUID, or free label when source_kind = external
  "source_name": "Internet",              // projection
  "target_kind": "asset",                 // asset | network | firewall (never external)
  "target_id": "uuid",
  "target_name": "WEB-01",                // projection
  "title": "Initial access via exposed RDP",
  "description": "Brute-forced local admin, first success 02:14 UTC",
  "edge_type": "initial_access",          // initial_access | lateral_movement | privilege_escalation | persistence | c2 | exfiltration | other
  "confidence": "confirmed",              // confirmed | probable | suspected
  "mitre_tactic": "TA0001",               // nullable
  "mitre_technique": "T1110.001",         // nullable
  "occurred_at": "2026-07-20T02:14:00.000Z",  // nullable
  "timeline_event_id": "uuid",            // nullable; SET NULL if event is deleted
  "timeline_event_time": "2026-07-20T02:14:03.120Z",  // projection (corrected UTC)
  "sequence": 1,                          // analyst ordering; ties broken by occurred_at, then created_at
  "ioc_ids": ["uuid", "uuid"],
  "created_at": "2026-07-21T09:05:00.000Z"
}
```

### 1.3 `InvestigationView` (presentation)

```json
{
  "id": "uuid",
  "name": "Intrusion pathway — DMZ to DC",
  "description": "Curated view for the client briefing",
  "state": { /* InvestigationViewState, §1.4 */ },
  "created_at": "...",
  "updated_at": "..."
}
```

`list_investigation_views` returns summaries (all fields except `state`).

### 1.4 `InvestigationViewState`

Stored as validated JSON in `investigation_views.state_json`; also the exact object the
frontend keeps in memory, so save/load is a pure serialize/parse.

```json
{
  "version": 1,
  "hidden_network_ids": ["uuid"],
  "hidden_node_ids": ["asset-<uuid>", "firewall-<uuid>", "external-Internet"],
  "filters": {
    "compromise": ["suspected", "infected"],   // empty array = no filter
    "only_with_sightings": false,
    "min_threat": "high",                       // null | low | medium | high | critical
    "time_from": null,                          // RFC 3339 or null; applies to attack edges
    "time_to": null
  },
  "display": {
    "show_topology_edges": false,
    "show_attack_edges": true,
    "show_ioc_badges": true,
    "show_step_numbers": true
  },
  "layout": "dagre",                            // dagre | grid | circle | concentric | breadthfirst
  "positions": [{ "id": "asset-<uuid>", "x": 120.5, "y": 340.0 }],
  "zoom": 1.25,
  "pan_x": -40.0,
  "pan_y": 12.5
}
```

Validation on save: `version` = 1; layout in the allowed set; `zoom`/`pan_*` finite
numbers; arrays of strings well-formed. Unknown ids are legal (entities may have been
deleted); loaders must skip them silently.

### 1.5 `InfectionSummary` (derived read model — never stored)

```json
{
  "entities": [
    {
      "entity_kind": "asset",
      "entity_id": "uuid",
      "sighting_count": 3,
      "max_threat_level": "critical",           // highest threat among sighted IOCs
      "ioc_ids": ["uuid", "uuid", "uuid"]
    }
  ],
  "iocs": [
    { "ioc_id": "uuid", "entity_count": 2,
      "entities": [{ "entity_kind": "asset", "entity_id": "uuid", "entity_name": "DC-01" }] }
  ]
}
```

## 2. Tauri commands — IOC sightings

### 2.1 `list_ioc_sightings`

| Input (all optional filters) | Type |
|---|---|
| `iocId` | string \| null |
| `entityKind` | `"asset" \| "network" \| "firewall"` \| null |
| `entityId` | string \| null |

Output: `ApiResponse<IocSighting[]>` ordered by `sighted_at` (nulls last), then `created_at`.

### 2.2 `create_new_ioc_sighting`

| Input | Type | Rules |
|---|---|---|
| `iocId` | string | must exist |
| `entityKind` | string | `asset` \| `network` \| `firewall` |
| `entityId` | string | must exist for that kind |
| `sightedAt` | string \| null | RFC 3339; must be a valid instant |
| `location` | string | trimmed; may be empty |
| `note` | string | trimmed; may be empty |
| `setCompromiseStatus` | `"suspected" \| "infected"` \| null | only honored when `entityKind` = `asset`; never downgrades an already-`infected` asset |

Output: `ApiResponse<IocSighting>`.
Effects: inserts the sighting; optionally updates `assets.compromise_status`; one
history commit containing one or two changes (`ioc_sighting` create, `asset` update).
Errors: unknown IOC/entity, invalid timestamp, invalid status value, locked case.

### 2.3 `update_existing_ioc_sighting`

Input: `id` plus the same mutable fields as create (`sightedAt`, `location`, `note`).
The IOC and target entity of a sighting are immutable — re-pointing a sighting is a
delete + create (keeps history semantics simple). Output: `ApiResponse<IocSighting>`.

### 2.4 `remove_ioc_sighting`

Input: `id: string`. Output: `ApiResponse<boolean>` (`true` on delete). Not-found is an error, matching existing `remove_*` commands.

### 2.5 `get_infection_summary`

Input: none. Output: `ApiResponse<InfectionSummary>` (§1.5). Read-only; safe to call
after any refresh trigger. This is the single source for IOC badges, "affected
entities" columns, and "IOCs seen here" panels.

## 3. Tauri commands — attack edges

### 3.1 `list_attack_edges`

Input: none. Output: `ApiResponse<AttackEdge[]>` ordered by
`sequence ASC, occurred_at ASC (nulls last), created_at ASC` — the canonical pathway
order used for step numbering and playback.

### 3.2 `create_new_attack_edge`

| Input | Type | Rules |
|---|---|---|
| `sourceKind` | string | `asset` \| `network` \| `firewall` \| `external` |
| `sourceId` | string | entity UUID must exist; for `external`, non-empty label (≤ 120 chars) |
| `targetKind` | string | `asset` \| `network` \| `firewall` |
| `targetId` | string | must exist |
| `title` | string | required, non-empty after trim |
| `description` | string | may be empty |
| `edgeType` | string | enum §1.2; default `other` |
| `confidence` | string | enum §1.2; default `suspected` |
| `mitreTactic` / `mitreTechnique` | string \| null | free-form, trimmed |
| `occurredAt` | string \| null | RFC 3339 |
| `timelineEventId` | string \| null | must exist when set |
| `sequence` | integer | ≥ 0; default = max(sequence)+1 at creation |
| `iocIds` | string[] | each must exist; deduplicated |

Additional rule: source ≠ target (same kind and id) — no self-loops.
Output: `ApiResponse<AttackEdge>`; one history commit.

### 3.3 `update_existing_attack_edge`

Input: `id` plus every field of §3.2 (full replace, like other `update_existing_*`
commands). Same validation. Output: `ApiResponse<AttackEdge>`.

### 3.4 `remove_attack_edge`

Input: `id: string`. Output: `ApiResponse<boolean>`.

### 3.5 Ripple behavior (implemented inside existing delete commands)

| Trigger | Effect on this domain (same transaction + history commit) |
|---|---|
| delete asset / firewall | delete its sightings; delete attack edges where it is source or target |
| delete network | dependency check first (existing pattern); error message enumerates blocking sightings/edges |
| delete IOC | delete its sightings; rewrite `ioc_ids` of every edge referencing it |
| delete timeline event | set `timeline_event_id = null` on referencing edges |

## 4. Tauri commands — investigation views

### 4.1 `list_investigation_views`

Input: none. Output: `ApiResponse<InvestigationViewSummary[]>` (name-sorted; §1.3 minus `state`).

### 4.2 `get_investigation_view`

Input: `id: string`. Output: `ApiResponse<InvestigationView>` including parsed `state`.

### 4.3 `save_investigation_view`

| Input | Type | Rules |
|---|---|---|
| `id` | string \| null | null → create; non-null → update (rename allowed) |
| `name` | string | required, unique (case-insensitive), ≤ 120 chars |
| `description` | string | may be empty |
| `viewState` | InvestigationViewState | validated per §1.4 (named `viewState` on the wire; stored as the entity's `state`) |

Output: `ApiResponse<InvestigationView>`. No history commit (presentation data).

### 4.4 `remove_investigation_view`

Input: `id: string`. Output: `ApiResponse<boolean>`.

## 5. Frontend pure functions (`src/lib/investigation-graph.ts`)

Pure, side-effect free, vitest-covered; importable by any React surface.

```ts
/** Build the full Cytoscape element list (before visibility is applied). */
function buildInvestigationElements(input: {
  networks: Network[]; assets: Asset[]; firewalls: Firewall[];
  connections: NetworkConnection[]; interfaces: NetworkInterface[];
  firewallInterfaces: FirewallInterface[];
  attackEdges: AttackEdge[]; infection: InfectionSummary;
}): cytoscape.ElementDefinition[];
// Node ids: `network-<id>`, `asset-<id>`, `firewall-<id>`, `external-<label>`.
// Attack edge ids: `attack-<id>`, class `attack-edge`, data: stepNumber, confidence, edgeType.
// Asset/firewall nodes carry data: compromise, sightingCount, maxThreat.

/** Decide which element ids are visible for the current state. */
function applyVisibility(
  elements: cytoscape.ElementDefinition[],
  state: Pick<InvestigationViewState, 'hidden_network_ids' | 'hidden_node_ids' | 'filters' | 'display'>,
  infection: InfectionSummary,
): { visibleIds: Set<string>; hiddenSummary: { id: string; label: string; reason: 'manual' | 'network' | 'filter' }[] };
// Rules: hiding a network hides members and their edges; an edge is visible only if
// both endpoints are; filters never hide a node that is an endpoint of a visible,
// manually-drawn attack edge unless manually hidden (pathway integrity).

/** Canonical pathway order (mirrors the backend ORDER BY). */
function orderAttackPath(edges: AttackEdge[]): AttackEdge[];

/** Steps visible at playback position n (1-based; 0 = none, edges.length = all). */
function playbackSlice(orderedEdges: AttackEdge[], step: number): Set<string>;

/** Round-trip helpers between live component state and the persisted view. */
function serializeViewState(input: {/* current UI state + cy camera */}): InvestigationViewState;
function parseViewState(raw: unknown): InvestigationViewState; // defensive; drops unknown ids/fields
```

## 6. Portable format additions (language-neutral)

Additive, backward compatible; `format_version` remains 1. Files written by older
builds simply lack the new arrays (parsers default them to empty); older builds ignore
unknown arrays in newer files.

### 6.1 Plain snapshot (`ExportData`)

Three new top-level arrays, exported after `iocs` / `timeline_events` and imported in
dependency order (sightings after iocs+assets+networks+firewalls; edges after all
endpoints and timeline events; views last):

```json
{
  "ioc_sightings":       [ /* stored fields of §1.1 (no projections) */ ],
  "attack_edges":        [ /* stored fields of §1.2 (no projections) */ ],
  "investigation_views": [ { "id": "...", "name": "...", "description": "...",
                             "state": { /* §1.4 */ }, "created_at": "...", "updated_at": "..." } ]
}
```

Snapshot import keeps the existing semantics: same case UUID required, existing ids
skipped, inserted/skipped counts per entity reported in `ImportSummary`.

### 6.2 Expert change bundle

`ioc_sighting` and `attack_edge` appear as `entity_type` values in `history_changes`
with full before/after JSON, merged field-by-field like every other entity.
`investigation_view` never appears in bundles.

### 6.3 Partial import (`dfir-investigator-partial` v1)

New accepted kinds and aliases: `ioc_sighting` (`ioc_sightings`, `sighting`,
`sightings`) and `attack_edge` (`attack_edges`, `attack_path`, `attack_paths`).
Same create/update/upsert semantics, dry-run preview, and validation paths as existing
kinds. Views are not accepted in v1.

### 6.4 Text report

New labeled sections "IOC Sightings", "Attack Pathway" (rendered in canonical pathway
order with step numbers), and "Saved Investigation Views" (name + description only).

## 7. Error catalog (new messages)

| Condition | Message pattern |
|---|---|
| Sighting target missing | `Referenced <kind> was not found` |
| More/fewer than one target | `A sighting must reference exactly one asset, network, or firewall` |
| Bad enum | `Invalid <field>: <value>` (existing `validate_enum` wording) |
| Self-loop edge | `An attack edge must connect two different entities` |
| `external` as target | `External origins can only be the source of an attack edge` |
| Unknown IOC in `iocIds` | `Linked IOC <id> was not found` |
| Duplicate view name | `An investigation view named "<name>" already exists` |
| Invalid view state | `Invalid view state: <detail>` |

All errors surface through the `ApiResponse.error` field; commands never throw across IPC.
